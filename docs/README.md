Troi is a chief of staff that lives on your Mac. It listens (hold a key, or say its name), sees when
you ask (the camera, or your screen), and does the work: files, apps, its own browser, your calendar,
meetings, code reviews, servers, reminders and reports. It keeps its memory in a vault you own and its
record on this Mac. It never deletes anything of yours: what should go waits for your approval, then
goes to the macOS Trash. Nobody but you can change how it behaves.

> **Not advice. Finished work.** Troi is wired into real systems and real files, remembers without a
> ceiling, and asks first whenever something cannot be undone.

## In one screen

1. Install it: `git clone https://github.com/Silo-One-Ug/troi-of-silo-one ~/troi-of-silo-one`, then
   `cd ~/troi-of-silo-one && ./install.sh`.
2. Give Terminal its permissions: Microphone, Camera, Screen Recording, Accessibility and Input
   Monitoring.
3. Double-click **Troi** on the Desktop. The welcome takes five minutes: your name, this Mac, a
   memory, a voice, your phone, a PIN.
4. Hold **Right Option** and speak.

## The parts

| Folder | What it holds |
| --- | --- |
| `console/` | The console app (Next.js, at `http://localhost:3100`): the welcome, the conversation, Library, Modes, Routines, Reports, Approvals, Eyes, Browser, and the Face, Hands, Files, Apps and Vault views |
| `troi-console/` | The agent's server (`http://127.0.0.1:8796`) and its tools: files, apps, the native hands, eyes, the browser, calendar, meetings, reports, Telegram, calls, the guard |
| `backtalk/` | The voice line: speech in, the agent's session, speech out |
| `ai-visualizer/`, `barehands/` | The face and the hands board |
| `vault-template/` | The starting vault the welcome creates when you have none |
| `brand/` | The logo: its generator and typeface; the files it makes are in `console/public/brand/` |
| `docs/` | These pages |
| `data/` | Everything Troi keeps (not tracked) |

`start.sh` starts everything. `install.sh` installs it. `troi-console/setup.py` renders the per-Mac
files (the agent's boot file `CLAUDE.md`, `.mcp.json`, `.claude/settings.json` and the components'
configs) from `troi-console/templates/`, and installs the background services.

## About these pages

They are published with [Mintlify](https://mintlify.com) from this directory, configured by
`docs.json`. That file is generated by `scripts/build-docs-nav.mjs` and not edited by hand: it takes
the navigation from the directory tree and each page's `title`, adds a redirect per page so the
`../section/page.md` links that GitHub follows also resolve on the site, and links the author's site
and the repository from the navbar and the footer. Each directory's `README.md` is the page people
edit; the `section-index.md` beside it is a generated copy, because the site will not serve a page
named README.

- Preview: `cd docs && npx mint@4.2.928 dev`, then open `http://localhost:3000` (the version CI
  uses; `mint@latest` fails whenever its dependency is not yet published).
- After adding or renaming a page: `node scripts/build-docs-nav.mjs`.
- Before pushing: `npx markdownlint-cli2` at the repository root, and
  `node scripts/build-docs-nav.mjs --check`.
- Publishing: connect the repository in the Mintlify dashboard with `docs` as the documentation
  folder; every push to `main` deploys.
